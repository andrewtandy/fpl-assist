# S00: Foundations

- **Dates:** 2026-10-11
- **PRs:** #1, #2, and this note

## Goal

Turn the existing Vue app into a repository ready for the Azure data layer: a monorepo layout with a folder per layer, a working CI gate protecting `main`, and the decisions that are hard to reverse recorded before any infrastructure exists.

## What shipped

- **Repository:** git history, a private GitHub remote and a `main` trunk. The `.gitignore` covers secrets, local env files, build output, and the Terraform, Python, Azure Functions and dbt artefacts still to come.
- **Layout:** the app, its Cloud Function and the Firebase config moved into `app/`. Empty `infra/`, `pipeline/`, `transform/`, `docs/adr/` and `docs/sprints/` folders, each with a README. The Firebase build, the emulators and the local app were checked after the move.
- **CI:** `.github/workflows/app.yml` runs on every PR and push to `main`. It typechecks and builds the frontend, then lints and builds the function.
- **Tooling fixes:**
  - `vue-tsc` upgraded from 1.8 to 2.x, because typecheck had been crashing on TypeScript 5.9.
  - The function's ESLint config now extends `eslint-config-prettier`, so ESLint checks code quality and Prettier owns formatting.
- **Branch protection:** a ruleset on `main` requires a PR (squash only, 0 approvals), a passing `build` check with the branch up to date, and linear history. Force pushes and deletions are blocked.
- **Decisions:**
  - ADR-000: why Azure.
  - ADR-001: raw lands in Blob before SQL.
  - ADR-005: UK South, with CAF-style names such as `rg-fplassist-dev-uks`.
- **Draft API history check:** every past gameweek of the current season can be fetched again, so backfill from GW1 will work. Previous seasons are not available. Point-in-time state (player news and status, ownership between gameweeks, in-match event order) only exists once the poller captures it. No stopgap capture was needed.

## What slipped

- **Prettier is a stated convention but not configured:** there is no `.prettierrc` and no format check in CI. Add it before the codebase grows, in a single formatting-only PR so the reformat doesn't hide real changes.
- **Not checked against the plan:** this note has not been compared line by line with the S00 tickets in the plan document. Check for any missed tickets before starting S01.

## Lesson

Check that a gate works before relying on it. Two checks here looked healthy but weren't. `npm run typecheck` had been crashing, not passing, so type errors would have slipped through. The first CI workflow's path filter would have left docs-only PRs waiting forever for a required check that never ran. A check that never runs or always crashes looks a lot like one that passes, so each new gate needs one deliberate run to prove it fails when it should.
